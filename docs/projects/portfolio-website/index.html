Portfolio Website & Self-Hosted Server

This site, built with React and Tailwind, and the Mac mini at home that serves its photo and projects API.

This site is a personal portfolio I built from scratch with React 19, Tailwind CSS v4, and Vite. Its photos come from a Mac mini I run as a server, which exposes a REST API for photos and projects and sits behind Cloudflare for caching and traffic analytics.

The site

The front end is responsive, with dark mode and animated theme transitions, fades between pages, and a filterable masonry photo gallery. Every page is also prerendered to plain HTML when the site is built, so link previews and search engines see the real content without having to run any JavaScript.

Deploying is automatic. When I push to the portfolio-web repository on GitHub, Cloudflare Pages picks up the push, runs pnpm build (which type-checks the code, bundles it with Vite and prerenders every page), and deploys the result to Cloudflare’s CDN, which serves eddie-lai.com worldwide.

The server and photo API

The API is an Express server on my Mac mini. Cloudflare reaches it through a Cloudflare Tunnel: cloudflared on the Mac mini opens the connection outward, so the Mac mini doesn’t need any open ports. Each photo comes back with its full EXIF metadata (camera, lens, focal length, aperture, shutter speed and ISO), along with a category, tags, and its most prominent colors, which the gallery’s category and color filters use. The metadata lives in PostgreSQL, which Express reads through Prisma.

The API is rate-limited to 100 requests per 15 minutes per client and only accepts browser requests from this site. The processed images are served with a one-year cache lifetime, so Cloudflare can answer repeat requests for them from its cache instead of the Mac mini.

Since the API runs on hardware at home, I also have Cloudflare watching it: if the Mac mini loses its connection to Cloudflare or the server becomes unreachable, Cloudflare emails me, so I find out about an outage before a visitor does.

Each photo is one row of a Prisma model in PostgreSQL. The API returns those rows as JSON, and the site maps each one into its own, slightly different shape for the gallery to use.

The API deploys itself too. Its repository has a GitHub Actions workflow that runs on every push to main: the runner installs cloudflared and connects over SSH tossh.eddie-lai.com through Cloudflare Access. On the Mac mini it pulls the new code, installs dependencies, builds, runs the database migrations, and reloads the server under pm2, which keeps it running.

Adding photos

To add photos, I copy the originals from my laptop to the Mac mini with rsync or scp over SSH, using the Mac mini’s address on my Tailscale network rather than the public internet. They land in ~/photos/unprocessed, which a chokidar watcher keeps an eye on. Once a new.jpg or .jpeg has stopped changing for two seconds, so it’s finished copying, the watcher adds it to a queue, and processPhoto works through the queue one photo at a time, turning each into a gallery entry:

  • It skips any photo that’s already in the database, deleting the duplicate original.
  • It reads the EXIF data with exifr.
  • It finds the five most common colors with sharp, which feed the gallery’s color filter.
  • It asks the llava model, running in Ollama on the Mac mini, for a one-sentence description, a category and five tags.
  • It encodes a WebP of at most 350 KB. Instead of a fixed quality, it binary-searches qualities from 40 to 90 for the highest one that fits, and if even the lowest is too big, it shrinks the image by a quarter and tries again. Widths are capped at 2,560 pixels.
  • It deletes the original and saves the photo’s row to PostgreSQL.
